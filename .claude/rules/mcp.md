# MCP server (`isx mcp`)

`isx mcp` serves the Model Context Protocol over stdio so an agent on the host can use isx instances -- or, through the proxy, an agent in an instance branched with `--mcp-client`. DESIGN.md "MCP server: delegating work to isx instances" has the rationale; these are the invariants.

**No Quarkus extensions for it.** The protocol is hand-rolled (`JsonRpc`, `McpServer`, `StdioTransport`) because the Quarkus MCP extension, even initialized on demand, added ~1.7 ms (+55%) to every isx command's startup. Anything new here must not add runtime-init work to other commands: measure native `hyperfine 'isx --help'` against main if in doubt. Messages are Jackson trees; no `@RegisterForReflection` DTOs.

**Stdout is the protocol channel.** `StdioGuard.install()` runs first: the transport owns fd 0/1, `System.out` goes to stderr, `System.in` is empty, `Headless.enable()` turns off `TerminalProgress` animation and makes `Prompts.console()` return null. Code reachable from a tool must never read the console, call `InitCommand.requireInit()`, `ProxyHealthCheck.requireProxy` or anything else that prompts or `System.exit`s -- turn the condition into a `ToolError` saying what to ask the user. A `ToolError` is an `isError` result for the model; JSON-RPC errors are for protocol faults only.

**Trust model.** Definitions come from `ImageDef.loadTrusted()` only -- `isx mcp` runs in the agent's repository, whose `.incus-spawn/` must not even override a parent of an approved template -- and are passed to `BranchFlow.preflight`. Templates: listed in `mcp.templates`, not built from a project-local definition (`BuildSource.usedProjectLocal()`), `TYPE_BASE`, built (`TemplatePolicy`); config re-read on every call. Instances: created only through `BranchFlow` with `Request.defaults()` -- never expose network mode, accounts, GUI, KVM, inbox or resources as tool arguments. Forks (`create_instance(from_instance)`, #1013): the source must be held and stopped, its lineage passes `TemplatePolicy.requireLineage` (listed, trusted, not project-local; need not be built), and it goes through `BranchFlow` with the source instance as `source`; the fork's task records are cleared (`TaskScripts.clear()`) or the fork is removed. An instance's template is `McpSession.templateOf()` -- `PROFILE`, falling back to `PARENT`, which for a fork names its source. Every tool naming an instance calls `McpSession.requireOwned()` (registry *and* the `mcp-session` stamp from Incus) once, at the tool boundary, and passes what it checked down -- `requireRunning()` for one that runs something in it, which refuses a stopped instance by naming `start_instance` (and any other non-running state by sending the agent to the user, since `start_instance` starts only a stopped one); `wait_any` takes its ids with `Tasks.requireHeld()`, since waiting copes with an instance it cannot ask. `metadata()` and `mcpInstances()` carry the Incus status as `InstanceBackend.STATUS` from the same read; every task goes through `Tasks.require()`. The only ways into the registry besides creating are `McpSession.resume()` (an instance session taking back what its own stamp names, below) and `McpSession.adopt()`: same `mcp-owner`, not kept, not busy, template still approved, holder dead (or released it, `Orphans.releasedByHolder`) unless `force`, and the stamp read back after writing it. `McpNoWritePathTest` forbids config/definition writes, builds, account changes, host processes and host file writes (except the audit log) in the package -- a change that needs one of those changes the trust model and should have to edit that test.

**Every result is structured too (#1010).** Each `McpTool` declares an `outputSchema` (built in `OutputSchemas`, closed objects, shared field names: `instance`, `template`, `task_id`, `state`, `exit_code`, `run`; a task `state` only from `TASK_STATES` and only where it is known (`list_instances` gives `Tasks.Task.state`, as last seen: `unknown` when nothing read how it ended, e.g. after a `cancel`), `already` for a no-op lifecycle call, `max_turns` as the run gets it, no placeholder values), and every successful result is `ToolResult.text(text, structured)` or `ToolResult.json(structured[, note])`; the text for the model stays prose. A failure is a `ToolError` whose thrower names its `ToolError.Code` (no default constructor; `Args` errors are `invalid_argument`, an escaping `IncusException` is `unavailable`, another isx operation holding the instance is `busy`, a `BranchFlow.preflight` refusal in `create_instance` is `refused` because the user must act, as is a proxy older than `/activity` in `instance_activity` (`ProxyActivity.Outdated`); only `unavailable` and `busy` may succeed on a retry as is) and becomes an `isError` result with **no `structuredContent`** and the code in `_meta["dev.incusspawn/error"]` -- the 1.x TypeScript SDKs validate `structuredContent` even on errors, and Claude Code ships them. A schema change must update the golden `cli/src/test/resources/mcp/output-schemas.json` (`McpOutputSchemaTest`, `-Dmcp.output-schemas.update=true`); `StructuredResults` (test) checks every result `McpToolsTest`/`DelegationToolsTest` produce against its schema with networknt's 2020-12 validator, and `everyToolReturnsStructuredContentMatchingItsSchema` must reach every tool, so a new tool needs a step there.

**Nothing an agent sends reaches a shell unquoted.** `ExecScript.quote()` for values, environment names validated, task run scripts sent as base64, instructions and prompts on stdin. Test hostile input in a real bash (`ExecScriptTest`, `TaskScriptsTest` run the generated scripts locally, the latter with stubs for `sudo`/`systemd-run`/`systemctl`/`su`/`claude`).

**Lifecycles.** Session id is `<pid>-<start>` (`SessionId`; on Linux `/proc` starttime ticks, see DESIGN.md), or `instance:<name>:<grant>` for a coordinator instance (below), read only for liveness: an instance belongs to its `mcp-owner`. Names are reserved before the copy; `max-instances` counts the user's instances across sessions (`Orphans.othersOf`), and `max-concurrent-tasks` the user's busy tasks: this session's registry plus `TaskScripts.busy()` asked of each running instance another session holds or orphaned, or kept by a live one (`McpSession.taskInstancesElsewhere`; `InstanceBackend.running()` from the same listing), in parallel, nothing when there are none, recounted on every reservation, each task id once, named per instance in the refusal; an instance failing counts zero, and one silent past `Tasks.elsewhereTimeout`, or slower than half of it, is not asked for `elsewhereCooldown` and counts zero meanwhile (never a frozen earlier answer); every `TaskScripts` read of a task file the host waits on goes through `ifFile` (`readFile` for `cat`; `ifFile(f, "read -r k")` on the poll path, which avoids a subshell), which opens it read-write -- never waiting on a FIFO, not even one swapped in after the path was checked (#1035, #1080) -- and reads only if `/dev/fd/3` is a regular file; never `[ -f F ] && cat F`. Every write the host waits on (`launch`, `cancel`, `recordExit`, `exec`'s pid file) goes through `writeAside`: into a `mktemp` file, then `mv -fT` over the target, which never opens it and fails on a directory (#1074); the steps are joined by `&&` and a failure removes the temp file, so a failed write (a full disk) puts nothing in place -- an empty `exit-<n>` would read as finished with no code -- and `launch`, under `set -e`, adds `|| exit 1`, since `set -e` ignores a failing `&&` list. `exec` writes its pid file in a subshell, so `writeAside`'s `w` never replaces a variable the command was given. `diff()` reads `base.txt` and the index it copies the same way, and runs under the guest's `timeout` (`DIFF_LIMIT_SECONDS`), since git opens repository files no script can check; a diff past it exits non-zero, which `Tasks.run` makes `unavailable` (#1105). `ExecScript.kill` reads the pid file through `readFile`; the probe is `InstanceBackend.probe` (agentuser's uid, no login shell, bounded: see incus.md), never more than one per instance (`Tasks.probing`), and `Orphans.probe` uses it too (no answer = in use); guest output is read with `TaskScripts.taskIds()`, which ignores anything that is not a task line. Ending a session never destroys: `release()` (end of input, shutdown hook) stamps `mcp-orphaned`; `Orphans.sweep` at the next session start stamps orphans nobody stamped and destroys those past `mcp.orphan-grace-hours`, skipping kept, busy, just-adopted and in-use ones (a stopped one is never in use and is not probed, and `destroyIfHeldBy(..., onlyIfStopped)` re-checks under its mark that it is still stopped) (`Orphans.probe`: `Presence` -- a pts process or a Claude Code without the `ISX_MCP_TASK` marker -- or an agent task `TaskScripts.unfinished()` finds running or cannot ask systemd about (not background commands, which may never end; a run a restart cut off reads as over); the sweep destroys through `InstanceBackend.destroyIfHeldBy()` (`InstanceDestroyer.deleteHeldIf`: mark `pending-op`, then re-read the holder) and `adopt()` reads `pending-op` after its stamp and waits for a mark to resolve (`settled`), so the two never both proceed; `mcp-orphaned` is `<time> <session>` and counts only for that holder (`Orphans.orphanedSince`); unreachable counts as in use). A running orphan past grace kept only for an unfinished delegate (`Orphans.Use`: not attended) is stopped as dormant (#1028) once `Orphans.quiet` finds no task-file write (`TaskScripts.agentIdle()`, in the same probe) and CPU growth under `QUIET_CPU_SHARE` between samples at least `MIN_SAMPLE_GAP` apart (`InstanceBackend.cpuUsage`, sample in `mcp-cpu-sample`; a sweep closer to the last sample neither compares nor records, so the probes' own CPU is not held against a tiny allowance) for `mcp.dormant-after-hours`, through `stopIfHeldBy` (mark, re-read the holder, stamp `mcp-dormant` *before* the stop, and take it back if the stop fails and the instance still runs); a stopped orphan with a `mcp-dormant` naming its holder (`Orphans.dormantSince`) waits `mcp.dormant-grace-hours` instead of being destroyed at once; `adopt()` clears `mcp-cpu-sample` and is refused `busy` (holding it) if the sweep's `stopping` mark outlasts `settled`; `adopt_instance` then calls `McpSession.wakeIfDormant()` on every adoption, a repeat included, which starts a held instance found stopped with any `mcp-dormant` (progress and audit line) and clears the stamp only after, so the retry `unavailable`/`busy` promise is the same call. `start_instance` and `stop_instance` clear a leftover `mcp-dormant` (`McpTools.notDormant`), so an instance its holder started or stopped on purpose is never woken by a later adoption. Task ids carry a random per-session tag (they outlive the session); `Tasks.adopt()` rebuilds them from `TaskScripts.list()`. A task is `attached` when `Presence` finds a Claude Code resuming its `session_id` or working in its recorded physical `cwd`; `send_message` refuses then. A delegate's `model`/`max_turns` (`Tasks.Profile`) live on the task and in its directory, so later runs and adopting sessions keep them; `max_turns` never exceeds `mcp.delegate-max-turns` (refused at the call, clamped for a recorded one), and a chosen model passes `ModelCheck` in the instance once the run's slot is reserved, before it launches (`Tasks.launch`'s `check`; under `timeout`; cached per template, the account `InstanceBackend.effectiveAccount` resolves the pin to now, and model; refusals not cached; only a `result`/`success` event with exit 0 passes, and a turn naming a model is checked even if it is the task's). The permission mode is never a tool argument. `ask` (`AskScript`) runs the producer and a tool-less `claude -p --model <summary-model>` in the instance, never on the host. Exec has no default timeout; cancellation kills the command's `setsid` session. Tasks are systemd units in the guest (`TaskScripts`), but `su -` inside the unit goes through PAM, which moves the run into a user session scope: the unit's cgroup does not contain it, so anything that must find or stop a task's processes (`cancel`, `Presence`) goes by the `ISX_MCP_TASK` environment marker every run exports. A run becomes `current` only once `systemd-run` succeeded, and a reservation is undone on any failure, building its script included. their state is the files under `~/.isx-mcp/tasks/<id>/`, and unit state is read with `sudo -n systemctl` (an unprivileged session cannot reach the system bus in a container). Poll with `TaskScripts.states()` (one cheap exec per instance), not `status()`, which carries the output tail. An `unknown` answer (systemd not reachable) never changes a task's recorded state, and an instance that cannot be probed only loses its tasks once it is gone (`Tasks.forgetInstance`, also called by `destroy_instance`); "gone" means a 404 (`InstanceBackend.metadata()` throws on any other failure) -- a stale task must neither free a slot early nor block every later task. A status read must exit 0 even before the run has written anything. A run is finished when its `exit-<n>` file exists, so it is always written aside and renamed into place (`recordExit`), never seen empty. A unit that is inactive with no exit file is `lost` -- except while `cancel` sweeps it: `cancel` stamps `cancelling-<n>` with the time before stopping the unit and records 143 only after the kill sweep, and every state read calls such a run `running` while the stamp is under five minutes old and not in the future (`CANCELLING`; the stop alone may take systemd's 90 s); otherwise -- once the exit file has been looked at again, since a cancel records it before removing its stamp and may finish between the two checks -- it is a cancel that died midway and the run is lost after all. The stamp is guest-writable data: only digits reach the arithmetic (bash evaluates an expression there). `status()` and `states()` take their state from `RUN_STATE` too, so the rules exist once, in the guest. `stop_instance` refuses while a task runs unless `force`, which `cancel`s them first (a stopped instance cannot be asked, so a task left `running` would hold its slot); `start_instance` runs `InstancePrep.prepare()`, which throws `Refused` instead of printing, then `Tasks.adopt()`s the instance's task records (an instance adopted while stopped could not be read). Destroys signal the proxy once per batch (`InstanceBackend.refreshProxy()`).

**Idempotency keys (#1011).** `create_instance`, `delegate` and `exec(background)` take an optional `idempotency_key` (`McpSession.checkKey`: 1-64 of `A-Za-z0-9._:-`; anything read back goes through `keyOf`, never trusted). A call whose key already made something returns it as the original result shape plus `replayed: true` (`OutputSchemas.REPLAYED`, never on `send_message`). There is no ledger: an instance's key is `Metadata.MCP_IDEMPOTENCY_KEY`, written by the copy request through `McpSession.stamps(purpose, key)` -- a fork never carries its source's, as `BranchFlow.create` gives the copy request an empty value (which unsets) for every `mcp-*` key of the source the caller does not stamp -- and a task's is `~/.isx-mcp/tasks/<id>/key`, written by `TaskScripts.launch` on run 1 and listed by `TaskScripts.list()` before `cwd` as `=<key>` (`-` for none, which is a valid key itself). Instance keys are matched among this host user's instances (`McpSession.keyed`, over the `Listing` that `reserve` then uses: a keyed create pays no extra request before the copy, and one listing after it); task keys only among this session's tasks (`Tasks.keyed`), so a guest-written key can only answer for a call naming its own instance. Replay is decided before anything about the instance is compared with the call (`McpSession.replayable`): a copy carries its source's config, `PARENT` included, until `configureBranch`, so an instance still being made -- by this session (`busy`) or a live one (`not_held`, naming `adopt_instance`) -- is refused as such, never as a mismatch whose advice ('use a new key') would make a second one; kept -> `refused`; held here -> as is; an orphan, or one its holder released (`Orphans.releasedByHolder`) -> `adopt()` with all its checks, then `Tasks.adopt`, and a running instance whose tasks cannot be read is let go of again and refused `unavailable` (a repeated delegate would not find its task). Only then is a key asking for another template/source (`requireSameInstance`), instance or kind of task `invalid_argument`, never redirected; `name_hint`/`purpose` are cosmetic and ignored. A key whose create or launch is still under way in this session is `busy`, decided under the reservation lock (`reserve`, `Tasks.reserveNow`); `delegate(template)` refuses a task key used elsewhere before branching (`Tasks.keyed(null, ...)`), and never removes its fresh instance once a repeat started the task there (`Tasks.startedUnder`). Across sessions every choice between two instances under one key is `McpSession.FIRST_MADE` -- Incus's `created_at` (`InstanceBackend.CREATED_AT`, read with the status), then name; never `user.incus-spawn.created`, which a copy carries from its source until `configureBranch` writes its own, after the copy is listed -- and a keyed create looks again after its copy (`McpTools.firstMadeUnder`) and, if it was not first, destroys its copy and replays the first: Incus lists a copy with its stamps from the moment its record is made, so of two racing creates the later one always sees the earlier. A dead session's copy that never got its `STATIC_IP` (cut off before `configureBranch`) is no instance a create promised and never counts: a copy never carries its source's address (`IncusClient.copy` unsets it in the request, pinned by `BranchOfABranchTest` and `InterruptedBranchTest`), so the address is what only `configureBranch` gives. `FakeBackend` lists a copy with its source's config before configuring it, as Incus does: test against that window. `delegate(template)` replaying an instance with no task under the key starts the task there. A replay is not refused by `max-concurrent-tasks`: it starts nothing.

**Activity (#898).** `instance_activity` is a read of the proxy's `/activity` (`ProxyActivity`, `common`) through `InstanceBackend.proxyActivity()`, after `requireOwned()` (a stopped instance has its last counts). The health address is resolved once and kept until a read fails; an unreachable or older proxy is a `ToolError` naming `isx proxy status`, never `requireProxy`. The result's field names are the contract: `counting_since` (per instance, when the proxy created its counters; absent only for an instance the proxy does not know; a client subtracts two reads only when both carry the same one), `requests`, `requests_in_flight`, `last_request_at`, `last_response_at`, `idle_seconds` (only with nothing in flight), and the API's own `input_tokens`/`output_tokens`/`cache_read_input_tokens`/`cache_creation_input_tokens`. Grow it additively.

**Task notifications (#1014).** `notifications/isx/task_changed` goes only to a client that listed `isx/task_changed` under `capabilities.experimental`; `McpServer`'s `experimental` map starts it after the `initialize` response, and without it nothing polls. `TaskWatcher` reports a task's state only when it differs from what it last reported, so a path that learns a state for free (`Tasks.launch`, `status`, `forgetInstance`) feeds `observe`/`forget`; `Tasks.cancel` appends `TaskScripts.watchBody()` to its own exec, because `stop_instance(force)` stops the instance right after and a stopped one cannot be asked; the poller covers every other task last reported running or never reported (`adopt` leaves it to the next round rather than pay an exec). `unknown` is never reported. Forgetting is `lost` (instance gone, reported only for a running task) or `released` (another session holds it, always reported), and is the last word: a forgotten id is tombstoned (a marked entry, not the `lost` state, which a later run moves on from), so a reading taken before and arriving after is dropped, until `Tasks.adopt` takes the task back (`revive`, which keeps the tombstone's run so a reading of an earlier one is still stale). Which of the two comes from `McpSession.whyNotHeld()`/`hold()`: every way out of the session's registry is `abandon(name, why)` (`destroy`, a 404 and a failed create are `GONE`, another session's stamp and `release()` are `RELEASED`), so a destroy racing a poll round is never reported as an adoption, and forgetting costs no request. `Tasks.forgetIfUnheld` decides and forgets under the lock `adopt` takes, and tells the watcher inside it, so an adoption completing meanwhile never has its tasks forgotten behind it. The poller (`Tasks.watchRound`) runs `TaskScripts.watch()`, one exec per instance, for tasks last reported running; every `SLOW_EVERY`th round it also covers finished agents (`attached`) and calls `McpSession.hold()` per instance, whose one read says held, gone (`lost`) or released. An instance whose watch exec failed (stopped, unreachable) is skipped until the next slow round (`unanswered`). Tests run rounds themselves (`autoPoll = false`), never on the timer.

**A coordinator in an instance (#915).** `isx branch --mcp-client` stamps `Metadata.MCP_CALLER` (`mcp-caller`); being an `mcp-` key, `configureBranch` drops it from every copy, and `IncusInstanceBackend.branch` refuses it from the MCP path -- no agent makes a coordinator. The proxy serves `https://mcp.isx.internal/mcp` (`ProxyConfig.MCP_DOMAIN`, a built-in intercepted domain answered by `McpBridge`, never relayed) to a caller `InstanceRegistry.identifyMcpCaller()` passes: address, per-start secret (`X-Isx-Instance-Secret`) and stamp, before any body is read. Each session is a host `isx mcp --caller-instance <name>` bridged over stdio (Streamable HTTP: POST answered as an event stream with keepalive comments, notifications on GET, DELETE ends; 404 means initialize again); one per instance, a new `initialize` ending the previous process before the next starts, or two registries would each count only their own instances against `max-instances`. The child re-checks the stamp. The session id is `instance:<name>:<grant>` (`SessionId.ofInstance`; the grant is the stamp's random value, `Metadata.newMcpCallerGrant()`, so a coordinator recreated under the same name is another session and never holds its predecessor's workers); `CallerLiveness` says it is alive while the instance exists with that grant (a failed read is alive), `release()` does nothing for it, and `McpSession.resume()` takes back its instances (one listing, before serving; tasks of running ones in the background) -- only those `adopt` would take: one whose template is no longer approved is released instead (`mcp-orphaned` naming the holder, which `Orphans.releasedByHolder` makes an orphan to every session though the holder lives), and a released one is never taken back. Tools and limits are the stdio ones; never add a tool argument or behaviour that only one transport has.

**Set up by `isx init`.** The "Agent Access over MCP (experimental)" step (`InitCommand.setupMcp`, default off, skipped without a host `claude` or a console) registers the server with `claude mcp add --scope user isx -- <isx> mcp` and asks, per template whose chain installs the `claude` tool, whether to approve it; templates approved by hand that it does not ask about are kept. Host calls (`claudeMcpRegistered`, `registerClaudeMcp`, `isxPath`, `templateBuilt`) are overridable seams; `McpInitFlowTest` drives it. It needs no `INIT_VERSION` bump: nothing on the host changes unless the user opts in.
