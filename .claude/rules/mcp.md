# MCP server (`isx mcp`)

`isx mcp` serves the Model Context Protocol over stdio so an agent on the host can use isx instances. DESIGN.md "MCP server: delegating work to isx instances" has the rationale; these are the invariants.

**No Quarkus extensions for it.** The protocol is hand-rolled (`JsonRpc`, `McpServer`, `StdioTransport`) because the Quarkus MCP extension, even initialized on demand, added ~1.7 ms (+55%) to every isx command's startup. Anything new here must not add runtime-init work to other commands: measure native `hyperfine 'isx --help'` against main if in doubt. Messages are Jackson trees; no `@RegisterForReflection` DTOs.

**Stdout is the protocol channel.** `StdioGuard.install()` runs first: the transport owns fd 0/1, `System.out` goes to stderr, `System.in` is empty, `Headless.enable()` turns off `TerminalProgress` animation and makes `Prompts.console()` return null. Code reachable from a tool must never read the console, call `InitCommand.requireInit()`, `ProxyHealthCheck.requireProxy` or anything else that prompts or `System.exit`s -- turn the condition into a `ToolError` saying what to ask the user. A `ToolError` is an `isError` result for the model; JSON-RPC errors are for protocol faults only.

**Trust model.** Definitions come from `ImageDef.loadTrusted()` only -- `isx mcp` runs in the agent's repository, whose `.incus-spawn/` must not even override a parent of an approved template -- and are passed to `BranchFlow.preflight`. Templates: listed in `mcp.templates`, not built from a project-local definition (`BuildSource.usedProjectLocal()`), `TYPE_BASE`, built (`TemplatePolicy`); config re-read on every call. Instances: created only through `BranchFlow` with `Request.defaults()` -- never expose network mode, accounts, GUI, KVM, inbox or resources as tool arguments. Forks (`create_instance(from_instance)`, #1013): the source must be held and stopped, its lineage passes `TemplatePolicy.requireLineage` (listed, trusted, not project-local; need not be built), and it goes through `BranchFlow` with the source instance as `source`; the fork's task records are cleared (`TaskScripts.clear()`) or the fork is removed. An instance's template is `McpSession.templateOf()` -- `PROFILE`, falling back to `PARENT`, which for a fork names its source. Every tool naming an instance calls `McpSession.requireOwned()` (registry *and* the `mcp-session` stamp from Incus) once, at the tool boundary, and passes what it checked down -- `requireRunning()` for one that runs something in it, which refuses a stopped instance by naming `start_instance` (and any other non-running state by sending the agent to the user, since `start_instance` starts only a stopped one); `wait_any` takes its ids with `Tasks.requireHeld()`, since waiting copes with an instance it cannot ask. `metadata()` and `mcpInstances()` carry the Incus status as `InstanceBackend.STATUS` from the same read; every task goes through `Tasks.require()`. The only way into the registry besides creating is `McpSession.adopt()`: same `mcp-owner`, not kept, not busy, template still approved, holder dead unless `force`, and the stamp read back after writing it. `McpNoWritePathTest` forbids config/definition writes, builds, account changes, host processes and host file writes (except the audit log) in the package -- a change that needs one of those changes the trust model and should have to edit that test.

**Nothing an agent sends reaches a shell unquoted.** `ExecScript.quote()` for values, environment names validated, task run scripts sent as base64, instructions and prompts on stdin. Test hostile input in a real bash (`ExecScriptTest`, `TaskScriptsTest` run the generated scripts locally, the latter with stubs for `sudo`/`systemd-run`/`systemctl`/`su`/`claude`).

**Lifecycles.** Session id is `<pid>-<start>` (`SessionId`; on Linux `/proc` starttime ticks, see DESIGN.md), read only for liveness: an instance belongs to its `mcp-owner`. Names are reserved before the copy; `max-instances` counts the user's instances across sessions (`Orphans.othersOf`), and `max-concurrent-tasks` the user's busy tasks: this session's registry plus `TaskScripts.busy()` asked of each running instance another session holds or orphaned, or kept by a live one (`McpSession.taskInstancesElsewhere`; `InstanceBackend.running()` from the same listing), in parallel, nothing when there are none, recounted on every reservation, each task id once, named per instance in the refusal; an instance failing counts zero, and one silent past `Tasks.elsewhereTimeout`, or slower than half of it, is not asked for `elsewhereCooldown` and counts zero meanwhile (never a frozen earlier answer); `busy()`/`unfinished()` read only regular files (a FIFO would hold them); the probe is `InstanceBackend.probe` (agentuser's uid, no login shell, bounded: see incus.md), never more than one per instance (`Tasks.probing`), and `Orphans.inUse` uses it too (no answer = in use); guest output is read with `TaskScripts.taskIds()`, which ignores anything that is not a task line. Ending a session never destroys: `release()` (end of input, shutdown hook) stamps `mcp-orphaned`; `Orphans.sweep` at the next session start stamps orphans nobody stamped and destroys those past `mcp.orphan-grace-hours`, skipping kept, busy, just-adopted and in-use ones (a stopped one is never in use and is not probed, and `destroyIfHeldBy(..., onlyIfStopped)` re-checks under its mark that it is still stopped) (`Orphans.inUse`: `Presence` -- a pts process or a Claude Code without the `ISX_MCP_TASK` marker -- or an agent task `TaskScripts.unfinished()` finds running or cannot ask systemd about (not background commands, which may never end; a run a restart cut off reads as over); the sweep destroys through `InstanceBackend.destroyIfHeldBy()` (`InstanceDestroyer.deleteHeldIf`: mark `pending-op`, then re-read the holder) and `adopt()` reads `pending-op` after its stamp and waits for a mark to resolve (`settled`), so the two never both proceed; `mcp-orphaned` is `<time> <session>` and counts only for that holder (`Orphans.orphanedSince`); unreachable counts as in use). Task ids carry a random per-session tag (they outlive the session); `Tasks.adopt()` rebuilds them from `TaskScripts.list()`. A task is `attached` when `Presence` finds a Claude Code resuming its `session_id` or working in its recorded physical `cwd`; `send_message` refuses then. A delegate's `model`/`max_turns` (`Tasks.Profile`) live on the task and in its directory, so later runs and adopting sessions keep them; `max_turns` never exceeds `mcp.delegate-max-turns` (refused at the call, clamped for a recorded one), and a chosen model passes `ModelCheck` in the instance once the run's slot is reserved, before it launches (`Tasks.launch`'s `check`; under `timeout`; cached per template, the account `InstanceBackend.effectiveAccount` resolves the pin to now, and model; refusals not cached; only a `result`/`success` event with exit 0 passes, and a turn naming a model is checked even if it is the task's). The permission mode is never a tool argument. `ask` (`AskScript`) runs the producer and a tool-less `claude -p --model <summary-model>` in the instance, never on the host. Exec has no default timeout; cancellation kills the command's `setsid` session. Tasks are systemd units in the guest (`TaskScripts`), but `su -` inside the unit goes through PAM, which moves the run into a user session scope: the unit's cgroup does not contain it, so anything that must find or stop a task's processes (`cancel`, `Presence`) goes by the `ISX_MCP_TASK` environment marker every run exports. A run becomes `current` only once `systemd-run` succeeded, and a reservation is undone on any failure, building its script included. their state is the files under `~/.isx-mcp/tasks/<id>/`, and unit state is read with `sudo -n systemctl` (an unprivileged session cannot reach the system bus in a container). Poll with `TaskScripts.states()` (one cheap exec per instance), not `status()`, which carries the output tail. An `unknown` answer (systemd not reachable) never changes a task's recorded state, and an instance that cannot be probed only loses its tasks once it is gone (`Tasks.forgetInstance`, also called by `destroy_instance`); "gone" means a 404 (`InstanceBackend.metadata()` throws on any other failure) -- a stale task must neither free a slot early nor block every later task. A status read must exit 0 even before the run has written anything. A run is finished when its `exit-<n>` file exists, so it is always written aside and renamed into place (`recordExit`), never seen empty. A unit that is inactive with no exit file is `lost` -- except while `cancel` sweeps it: `cancel` stamps `cancelling-<n>` with the time before stopping the unit and records 143 only after the kill sweep, and every state read calls such a run `running` while the stamp is under five minutes old and not in the future (`CANCELLING`; the stop alone may take systemd's 90 s); otherwise -- once the exit file has been looked at again, since a cancel records it before removing its stamp and may finish between the two checks -- it is a cancel that died midway and the run is lost after all. The stamp is guest-writable data: only digits reach the arithmetic (bash evaluates an expression there). `status()` takes its state from `RUN_STATE` too (`state=`), so the rules exist once, in the guest. `stop_instance` refuses while a task runs unless `force`, which `cancel`s them first (a stopped instance cannot be asked, so a task left `running` would hold its slot); `start_instance` runs `InstancePrep.prepare()`, which throws `Refused` instead of printing, then `Tasks.adopt()`s the instance's task records (an instance adopted while stopped could not be read). Destroys signal the proxy once per batch (`InstanceBackend.refreshProxy()`).

**Activity (#898).** `instance_activity` is a read of the proxy's `/activity` (`ProxyActivity`, `common`) through `InstanceBackend.proxyActivity()`, after `requireOwned()` (a stopped instance has its last counts). The health address is resolved once and kept until a read fails; an unreachable or older proxy is a `ToolError` naming `isx proxy status`, never `requireProxy`. The result's field names are the contract: `counting_since` (per instance, when the proxy created its counters; absent only for an instance the proxy does not know; a client subtracts two reads only when both carry the same one), `requests`, `requests_in_flight`, `last_request_at`, `last_response_at`, `idle_seconds` (only with nothing in flight), and the API's own `input_tokens`/`output_tokens`/`cache_read_input_tokens`/`cache_creation_input_tokens`. Grow it additively.

**Task notifications (#1014).** `notifications/isx/task_changed` goes only to a client that listed `isx/task_changed` under `capabilities.experimental`; `McpServer`'s `experimental` map starts it after the `initialize` response, and without it nothing polls. `TaskWatcher` reports a task's state only when it differs from what it last reported, so a path that learns a state for free (`Tasks.launch`, `status`, `forgetInstance`) feeds `observe`/`forget`; `Tasks.cancel` appends `TaskScripts.watchBody()` to its own exec, because `stop_instance(force)` stops the instance right after and a stopped one cannot be asked; the poller covers every other task last reported running or never reported (`adopt` leaves it to the next round rather than pay an exec). `unknown` is never reported. Forgetting is `lost` (instance gone, reported only for a running task) or `released` (another session holds it, always reported), and is the last word: a forgotten id is tombstoned (a marked entry, not the `lost` state, which a later run moves on from), so a reading taken before and arriving after is dropped, until `Tasks.adopt` takes the task back (`revive`, which keeps the tombstone's run so a reading of an earlier one is still stale). Which of the two comes from `McpSession.whyNotHeld()`/`hold()`: every way out of the session's registry is `abandon(name, why)` (`destroy`, a 404 and a failed create are `GONE`, another session's stamp and `release()` are `RELEASED`), so a destroy racing a poll round is never reported as an adoption, and forgetting costs no request. `Tasks.forgetIfUnheld` decides and forgets under the lock `adopt` takes, and tells the watcher inside it, so an adoption completing meanwhile never has its tasks forgotten behind it. The poller (`Tasks.watchRound`) runs `TaskScripts.watch()`, one exec per instance, for tasks last reported running; every `SLOW_EVERY`th round it also covers finished agents (`attached`) and calls `McpSession.hold()` per instance, whose one read says held, gone (`lost`) or released. An instance whose watch exec failed (stopped, unreachable) is skipped until the next slow round (`unanswered`). Tests run rounds themselves (`autoPoll = false`), never on the timer.

**Set up by `isx init`.** The "Agent Access over MCP (experimental)" step (`InitCommand.setupMcp`, default off, skipped without a host `claude` or a console) registers the server with `claude mcp add --scope user isx -- <isx> mcp` and asks, per template whose chain installs the `claude` tool, whether to approve it; templates approved by hand that it does not ask about are kept. Host calls (`claudeMcpRegistered`, `registerClaudeMcp`, `isxPath`, `templateBuilt`) are overridable seams; `McpInitFlowTest` drives it. It needs no `INIT_VERSION` bump: nothing on the host changes unless the user opts in.
