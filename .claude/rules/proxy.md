# MITM TLS Proxy

`MitmProxy` (in `proxy/src/main/java/dev/incusspawn/proxy/`; the supporting `ProxyConfig`, `ProxyCredentials`, `ProxyHealthCheck`, `ProxyService` and `CertificateAuthority` live in `common/src/main/java/dev/incusspawn/proxy/`) is a TLS-terminating proxy that intercepts HTTPS to specific domains and injects real auth credentials, so containers only hold placeholder values. Key design:
- Listens on gateway IP:18443 (iptables redirects 443->18443 on the bridge)
- `authError` is set by credential injection, which only runs on **real container traffic** -- so on its own it makes the status wrong in both directions (a fixed failure still shown, a broken credential not yet noticed). `/health` therefore verifies the Vertex token itself via `claimAuthRevalidation()`, running `getVertexAccessToken()` through `executeBlocking` (it forks `gcloud`; never call it on the event loop from here). The gate declines in four cases and each one matters: **not `useVertex()`** (first line, before any lock or dispatch -- non-Vertex users must pay nothing); **a fresh cached token with no error** (`hasFreshVertexToken()`, read *outside* `authLock` -- taking `authLock` then the instance monitor while the traffic path takes them in the other order would risk deadlock); **a standing non-`VERTEX_AUTH_HINT` error** (OAuth needs `isx init`); and **the 10s throttle / in-flight flag** (a failing credential caches nothing, so every poll would otherwise fork `gcloud`). A probe failure calls `recordProbeAuthError`, **not** `setAuthError` -- the latter notifies, and the check runs on every poll. When adding a new credential source, give it a hint constant and decide explicitly whether it is machine-verifiable.
- `getVertexAccessToken()` is bounded at `GCLOUD_TIMEOUT_SECONDS` and rejects an empty token instead of caching it. Both matter because `/health` reaches this with no traffic to reveal a wedged `gcloud` or a blank credential.
- The proxy authenticates to Vertex with `gcloud auth print-access-token`, which reads the **gcloud user credential** -- so the remediation is `gcloud auth login`, not `gcloud auth application-default login`. `InitCommand.verifyVertexConfig()` uses the same command and must give the same hint.
- Per-domain certs signed by a custom CA (installed in templates during build). The CA lives at `~/.config/incus-spawn/ca.{crt,key}`; leaf certs are persisted by `CertStore` under `~/.config/incus-spawn/certs/` (`<domain>.crt`/`.key`, wildcards as `_wildcard.<domain>`) and reused across proxy restarts, re-minting only on miss/CA-rotation/near-expiry. Persisting is what keeps each leaf's `notBefore` stable: the proxy is relaunched frequently (macOS launchd `KeepAlive`), and re-minting on a host whose clock has jumped ahead of a lagging container clock (e.g. an Incus VM after macOS resume) produced certs the container rejected as "not yet valid". Certs are keyed by domain, never by container (a leaf is a function of `(domain, CA)`), so this composes with future per-container interception, which is a routing/DNS concern. `CertificateAuthority.BACKDATE_MS` backdates `notBefore` as a skew margin for the rare fresh-mint moments.
- **Certs are chosen per SNI name** by `InterceptedCertOptions` (Vert.x `keyManagerFactoryMapper`, run on a worker thread), not by a fixed keystore. dnsmasq sends names at *any* depth under an intercepted domain, but a wildcard SAN covers one label, so `certNameFor()` gives the exact domain or a wildcard for the name's own parent, minted on demand through `CertStore`. Two bounds, because the container picks the names: `MAX_ON_DEMAND_CERTS` counts on-demand certs **on disk** (so reloads/restarts don't reset it), and `MAX_SERVED_NAMES` counts distinct SNI names answered, since Vert.x caches an `SslContext` per answered name forever. With the old `<domain>`/`*.<domain>` JKS, a deeper name matched no alias and Vert.x served an arbitrary entry: `*.api.openai.com` for a GitHub host (#783). Anything else (off-domain, no SNI, over the cap) is refused: the mapper returns `null` and the default key manager holds **no** cert, so the handshake fails at once. Never refuse by throwing from the mapper -- Netty then hangs the connection until the handshake timeout. SNI names become file names, so `CertStore.get()` accepts only `CertStore.isHostname` names. `InterceptedCertOptionsTest` covers every shipped intercepted domain automatically.
- Both CA and leaf certs carry RFC 5280 key identifiers: SKI on the CA, SKI + AKI on leaves. Strict validators (OpenSSL 3.5, and so Python 3.13+, which turns on `VERIFY_X509_STRICT` by default) reject a chain without them -- including the trust anchor, so leaf-only extensions are not enough. A CA generated before this is re-issued on load over its **existing key** (`reissueWithSki`), which keeps every leaf valid and un-re-minted; the replaced cert is kept as `ca-superseded.crt`. Images stamped with that superseded fingerprint carry a stale-but-not-foreign anchor: `BranchCommand` lets them branch (the new cert is pushed into the instance by `InstancePrep`/`fixContainerCaIfNeeded` on first use) instead of demanding a rebuild the way a real CA rotation does.
- Claude credentials live in `claude.accounts`, a named map (`ClaudeAccount`, `type: api-key|oauth|vertex`) so several accounts can be configured at once; `claude.default` names the one instances use. `ClaudeConfig.accountFor(Predicate)` picks the default when it qualifies, else the first that does. Which accounts exist and which is the default are answered by `AccountResolver` against `ClaudeConfig.ACCOUNT_SHAPE`, the same rule as every namespace (a pre-accounts flat file presents as the account `default`; see `config.md`), so nothing outside `ClaudeConfig` branches on Claude. `ClaudeConfig`'s `isOauthMode()`/`getApiKey()`/`isUseVertex()` accessors are **derived from the resolved account**, so `ProxyCredentials`, `ClaudeSetup` and `PiSetup` read them unchanged. Both config classes bind Jackson **by field** (`@JsonAutoDetect` getters `NONE`) because the derived getters collide with the legacy field names -- an `@JsonIgnore` there disables the whole split property and a flat `config.yaml` silently stops deserializing. Account selection is **per instance** and **generic across config namespaces** -- see the next two bullets.
- **Per-instance accounts.** Three layers, resolved lowest-first: the namespace's `default` in config.yaml, the template's `accounts:` map (merged per key down `ImageDef.chain()` via `resolveAccounts`), and a per-instance override (`isx branch --account <ns>=<account>`, `isx account set`; `isx account unset` removes it). The last two are stamped as `user.incus-spawn.account.<namespace>` (`Metadata.accountKey`). Selection is always namespaced -- a bare name would fan out over whichever namespaces happened to have that account, so a namespace added later would silently widen an existing command. **Fail closed**: a pin to an account that is gone raises `AccountResolver.UnknownAccountException` and the request 502s; never fall back to the default, which in #351's case belongs to another client. `isx doctor` reports dangling pins. `AccountUsage` is the read-side view for humans (`isx account show`): the served account per namespace, who chose it -- recorded beside every pin as `user.incus-spawn.account-origin.<ns>` (`AccountOrigin`: `template:<name>`, `explicit`, `copied:<instance>`), written only through `AccountSelection.stampUpdates` so pin and origin never diverge -- and drift from the template's current `accounts:`; `ToolSetup.describeAccount()` describes an account without its credential. `isx init` warns before removing an account pinned by instances or named by templates, and its rename re-points pins via `AccountSelection.renameInInstances`, which renames an identity stamp only through `ToolSetup.renameBakedIdentity()` (GitHub keeps the fingerprint). **Default changes** move every unpinned instance: `isx init` (`changeDefaultAccount`) names them (`InstanceRegistry.accountStates` includes unpinned instances) and offers switch/keep/cancel; the proxy logs them on reload (`logDefaultChanges`). The registry reads `account-identity` stamps (`InstanceAccounts.bakedIdentities`), and `MitmProxy.refuseIfUnservable` fails closed -- `AccountSelection.UnservableAccountException`, 502 -- when the served account (pin or default) needs another Claude auth mode than the instance was built with (`AccountSelection.servingMismatches`), scoped to that credential's domains (`namespacesForDomain`, wildcards included); cached per registry record in the reload's `ConfigState`, so a result computed from the old config lands in a cache nothing reads any more. `accountStates` lists branches only -- never templates, whose pins would travel to all their branches.
- **The generic seam is one method.** `ProxyDef.accountConfigPath()` builds `<ns>.accounts.<account>.<config-path>` beside the existing `fullConfigPath()`; `ToolProxyResolver.resolveConfigValue` prefers it and falls back to the flat path when the namespace has no accounts *or the account omits that key* (a namespace may hold the token per account and other settings globally). That gives named accounts to every namespace at once, YAML-only tools included, with no per-tool code. The namespace is derived **per config entry** (`ProxyDef.namespaceOf`), not per tool: a tool may *borrow* another namespace's credential by naming it fully in `config-path` and declaring no `config-namespace` (`CopilotSetup` points at `github.token` to share the `gh` PAT). Keying off the tool's own namespace would leave `gh` authenticating as the pinned account while copilot used the flat token -- two GitHub identities in one container. `AccountResolver` does the tree-based resolution; `AccountSelection` does parsing/validation/stamping. `GitHubConfig`/`BobConfig`/`OpenaiConfig` extend `SpawnConfig.NamespaceConfig` so an `accounts:` block survives a save -- without it the block deserialized to nothing and the next save **deleted** it.
- **Caller identification.** `routeRequest`/`routeWebSocket` read `req.remoteAddress()`; iptables REDIRECT preserves the container's source address, and every branch has a static IP in `Metadata.STATIC_IP`. `InstanceRegistry` maps address -> (instance, accounts) from one `listJsonConfig()` call. An address two instances claim (a copy made before #815, or by `incus copy`) belongs to the one running claimant -- Incus will not start a second NIC on the same address -- and to nobody when none or several run; never to whichever is listed last. `isx branch`/`isx account set` poke it with **SIGUSR1** (`ProxyService.signalAccountRefresh`), not SIGHUP: pinning is instance state, and answering a branch -- the most common operation there is -- with a full reload would re-mint certs and re-push SSL options every time. `lookup()` must stay non-blocking (event loop); refreshes go through `executeBlocking` with single-flight, like `resolveHost`/`acquireVertexAccessToken`. Normalize `::ffff:` mapped addresses or every lookup misses and silently serves defaults. An unknown address gets the defaults on purpose: host traffic uses this proxy too. Build containers that pin an account are **not** unknown (#903): `BuildAccounts.start` claims them an address (`InstanceLifecycle.assignBuildAddress`, filtering on, guest keeps DHCP, leased addresses skipped) and stamps the template's pins before the first start, clears every `account-identity` stamp copied from the parent (else `refuseIfUnservable` would refuse the build its own template's account, or a changed default) -- reading them first, since `refreshInheritedIdentities` needs them after tool setup and `BuildAccounts.identityStamps` puts back the ones the build does not re-stamp -- and signals the proxy; `releaseBuildAddress` gives the address back once the template is stopped. A build pinning nothing is served the defaults either way and keeps plain DHCP. A new build path must do the same before anything in it goes through the proxy.
- **`security.ipv4_filtering` is load-bearing**, not incidental hardening: without it a container can re-address itself as a neighbour and spend that neighbour's credentials, so the whole model would be decorative. Set by `InstanceLifecycle.configureBranch` (a refused setting is retried without it and warned about, never fails the branch), re-armed on every stopped start by `InstanceLifecycle.prepareHostDevicesForStart` (so both `isx shell` and the TUI shell, and whatever merges them, must keep going through it -- `IpFilteringRearmTest`), which also restores it on instances the fallback below turned off. **Setting it succeeds even where it cannot be enforced** -- the failure appears only when the instance starts and Incus installs the per-NIC rules (`ebtables -t filter` under xtables, the nft equivalent otherwise), so a host without that kernel support would accept every branch and start none of them. The macOS appliance kernel needs `CONFIG_NF_TABLES_BRIDGE` for this (#905); its smoke test asserts it. `InstanceLifecycle.startInstance` is therefore the way isx starts an instance: it recognises that one failure, drops the setting, says plainly what is no longer enforced, and retries. Keep the match narrow -- it strips a security setting, so any other start failure must surface as itself.
- **Per-request credentials.** `RequestContext(domain, instanceName, creds, routing, usesDefaultCredentials)` replaces the bare `domain` parameter down `routeRequest -> handleApiRequest -> handleApiRequestWithBody -> sendApiRequest -> injectHeaders`. Routing is global (which domains are intercepted never varies by account); only the credential inside the entry does, so a pinned instance gets its own `ToolProxyRouting` built by the pure `buildRouting(list, warn)`. Everything derived from the config -- default credentials and routing, tool setups, the per-namespace indexes, and the `credentialsBySelection`/`mismatchesByInstance` caches -- is one immutable `ConfigState`, built eagerly by `useConfig()` (the single path for the `MitmProxy(..., ConfigFingerprint.Loaded)` constructor and `reload()`) and **replaced whole on every reload**. A late request writes only into the old state's caches, so a rotated token is never put back. Never add a lazy read of config or tool setups: it escapes the fingerprint and can revert a reload (#837). The Vertex *token* cache stays global on purpose: `gcloud auth print-access-token` returns the host's gcloud user credential regardless of project, so only region/project come off the per-request creds. `authError` transitions are gated on `usesDefaultCredentials()` -- a pinned instance's broken token is reported to that instance, but must not set or clear the host's own auth status.
- **What a build derives from an account is stamped and reconciled.** `ToolSetup.bakedAccountIdentity()` returns Claude's `effectiveType()` (two accounts of one mode leave the image identical) and GitHub's account name plus `#` and a 12-hex SHA-256 fingerprint of its token and email (`user.name`/`user.email` come from whoever the token belongs to, so a token replaced in place with another user's is a change of identity too -- #281; a stamp without a fingerprint, from an older build, is re-derived once). Namespaces that bake nothing return `""` and are freely interchangeable. Stamped at build as `user.incus-spawn.account-identity.<ns>`. On a re-point, a tool that `canRebakeForAccount()` is asked to fix itself up -- `GhSetup.rebakeForAccount` clears the git identity and asks the API again, which resolves through the proxy and so answers for the new account by itself. `AccountSelection.staleIdentities` maps each stale namespace to the *account* to re-derive for, and `InstanceLifecycle.reconcileAccountIdentities` drives that, stamping back the tool's current identity, and is called from **all three** places a pin can change or take effect: `BranchCommand` after start, `AccountCommand`'s `set` when the instance is running, and `InstancePrep` on the next `isx shell`/`isx run`. All three are needed -- only the last catches an instance branched `--no-start`, and without the first two an instance used over `incus exec`, SSH or an IDE would keep committing as the template's account for as long as nobody happened to run `isx shell`. A tool that cannot (Claude: the mode is in `/etc/profile.d`, which a running agent has already read) has the swap refused by `AccountSelection.incompatibilityReason`. A child template's build re-derives an identity inherited from its parent that no longer matches (`BuildCommand.refreshInheritedIdentities`, *after* tool setup: a parent without gh still carries a GitHub stamp, and an identity written first would create the `.gitconfig` whose absence is how `GhSetup` knows to write its git defaults) -- the copy carries the parent's `.gitconfig`, which gh's setup would otherwise keep while the end-of-build stamp claimed the current identity. `GhSetup.rebakeForAccount` is a no-op where `gh` is not installed, since every build stamps every namespace. `ClaudeSetup`/`PiSetup` `envEntries(params, selection)` and `GhSetup.install(c, params, selection)` all take the **template's** account, not the global default.
- Three auth modes for Anthropic domains (priority: Vertex > OAuth > API key): OAuth mode strips `x-api-key` and injects `Authorization: Bearer <token>` for Claude Pro/Max users; Vertex mode does three-way routing -- passthrough for Vertex-formatted requests, standard-to-Vertex translation for `/v1/messages` (using `VERTEX_ALLOWED_FIELDS` body allowlist), and direct forwarding for non-messages endpoints; API key mode replaces `x-api-key` with the real key. Anthropic auth is declared via `ClaudeSetup.proxy()` with `type: anthropic` but remains hardcoded in `MitmProxy` (too complex for the generic tool proxy system); `buildRouting()` filters `type: anthropic` entries from domain maps
- GitHub, Bob, and Codex/OpenAI credential injection is handled via tool-contributed proxy entries (see Tool System), not hardcoded. `ToolProxyResolver.resolve(SpawnConfig)` resolves configuration from `value`/`config-path`, uses `${configKey}` template substitution in auth fields, and produces a per-domain `ResolvedToolProxy` list. `MitmProxy` stores these in `toolProxyByExactDomain` (exact matches) and `toolProxyWildcardSuffixes` (wildcard suffix matches); `findToolProxy()` does exact-then-wildcard lookup. `isInterceptedDomain()` is an instance method (not static) to include tool proxy domains alongside built-in ones. `ProxyCredentials` only has Anthropic-specific fields (`anthropicApiKey`, `oauthToken`, Vertex settings) -- `ghToken`/`bobApiKey`/`openaiApiKey` have been removed
- WebSocket passthrough: handles Upgrade requests by establishing an upstream WebSocket connection (with credential injection via both Anthropic auth and tool proxy lookup), then relaying frames bidirectionally with keepalive pings and close-code propagation. Used by Codex CLI for `api.openai.com`
- Caches OCI blobs by SHA256, Maven/Gradle artifacts by repository path (confirmed with upstream per `ArtifactCacheTiers`, see below), and npm tarballs from `registry.npmjs.org` with ETag-based packument verification. All three commit through `Verification` (`fetchCacheAndServe`): nothing reaches the cache unverified
- **Maven/Gradle cache integrity** (#555, DESIGN.md "Maven/Gradle cache integrity"): serve a cached artifact only when a direct fetch would have returned the same bytes at its last confirmation with upstream, and that confirmation is recent enough. **`ArtifactCacheTiers`** (`artifact-cache:` `fresh`, default 2h; `max-stale`, default 7d) decides from the stored checksum's mtime, which `VerifiedArtifactStore` sets on commit and renews (best-effort) only on a match from an answer that could have evicted (`mayEvict`): fresh is served with no request, stale is served and confirmed in the background (single-flight, at most 16 in flight, the rest queued; a change evicts for the next request, an inconclusive answer expires the confirmation), older is **confirmed before serving**. `Revalidation.mayWithdraw` domains (Plugin Portal) never get the tiers. `artifact-cache:` stays a raw value in `SpawnConfig`: a typed binding would let a mistyped section fail the whole config.yaml. Hits are counted in `ArtifactCacheStats` and logged as one summary at most every 5 s, only after activity; don't add a per-hit log line back. Older is confirmed as `Revalidation` says per domain: `HEAD_CHECKSUM` (Central: a `HEAD`'s `X-Checksum-SHA1`, falling back to `.sha1`) or `SIDECAR` (portal, Gradle distributions). A domain without an entry is never cached. A miss is only the GET, committed if it matches the same response's `X-Checksum-SHA1` or the sidecar fetched afterwards; no usable checksum means served but not cached. Past the tiers, only an unreachable upstream (`SidecarAnswer.unreachable()`: connect failure or 5xx; 30s per-domain backoff) serves unconfirmed. `X-Checksum-SHA1` is what makes Maven skip its `.sha1` request: for a copy served on a trusted confirmation (`serveTrusted`) it is the stored checksum, and sidecar requests get the stored copy too, or Maven would pay the round trip the tiers save. For any other copy it must be upstream's **current** value, never synthesized from the store, which would turn the client's check against upstream into a check against our own cache. `Revalidation` is also the caching allowlist, and its javadoc states why a domain must be vetted even though hits are confirmed: offline serves are unconfirmed, and serves within the tiers not confirmed now (so they rely on the repository not changing or withdrawing releases), the confirmation must be sound for that repository (`SIDECAR` only where artifact and sidecar are published together and never replaced), and the cache is shared across instances without per-client authorization (public repositories only). Keep those reasons, not "immutability", in comments. `probeClient` (h2) needs its connection-level `readIdleTimeout` below `probeOptions()`' request timeout: it fires only while an exchange waits, and is the only thing that evicts a silently dead h2 connection (a request timeout resets just its stream). Keep `setHttp2MaxPoolSize` above 1, or bursts to HTTP/1.1-only or unreachable hosts serialize. `~/.m2` imports copy/reflink, never hardlink. Commit/reconcile/evict go through `VerifiedArtifactStore`'s striped lock; don't touch the cache files around it
- **Proxy lifecycle locking**: `ProxyService` guards mutating operations (`restart`, `stop`, `install`, `uninstall`, `startService`, `reinstallIfChanged`, `upgradeIfNeeded`) with a `HostLock` (`proxy.lock` in `configDir()`). Public methods acquire the lock then delegate to private `*Locked()` variants, because `HostLock` is not reentrant. When adding new operations that modify proxy service state, follow the same pattern.
- **The service execs `isx-proxy`, never `isx proxy start`**: the CLI dropped Vert.x when the proxy became its own module, so it cannot serve the proxy in-process. `install()` resolves `resolveProxyBinaryPath()` first and refuses to write the unit/plist without one (`printMissingProxyBinary()` names the JBang aliases, since JBang installs each separately -- issue #701). A unit exec'ing `isx proxy start` restarts itself forever: the command sees the service installed and unhealthy and restarts the unit it is running under, with `reset-failed` clearing systemd's rate limiter each pass. Units already on disk are covered three ways: `ProxyStartCommand` resolves the proxy binary *before* any service management and exits `EXIT_CONFIG` when it is missing (restarting cannot fix an absent binary); `ProxyService.isSupervisedInvocation()` matches systemd's `INVOCATION_ID` against the proxy unit's own invocation so a legacy unit's `isx proxy start` launches the proxy instead of restarting itself; and on macOS, where launchd has no `RestartPreventExitStatus` (a `KeepAlive` job exiting 78 is simply restarted) and `RunAtLoad` would revive a booted-out job at the next login, `haltUnusableMacOsService()` boots the job out **and** deletes the plist, declining whenever the proxy still answers on 127.0.0.1. `upgradeIfNeeded()`/`reinstallIfChanged()` call it before `needsMacOsPlistUpdate()`, which cannot describe a plist whose binary is gone. `startScriptIsStale()` compares the exec line, which no legacy `isx proxy start` script can match, so upgrades rewrite them.
- **The foreground `isx proxy start` stops its child on shutdown**: `ProxyStartCommand.ForegroundProxy` registers a hook, before it starts the child, that sends the `isx-proxy` child SIGTERM and SIGKILLs it after 15 s (and skips the abnormal-exit diagnosis, since that stop was asked for), so killing the CLI alone does not orphan a proxy that keeps the ports (#882). `ProxyStartForegroundTest` drives it in a separate JVM.
- **Bridge DNS is `address=/<d>/<gateway>` + `local=/<d>/`** per intercepted domain, inside a `# BEGIN`/`# END incus-spawn intercepted domains` block in `raw.dnsmasq` (`BridgeDns`; `ProxyConfig.writeBridgeDns()`/`clearBridgeDns()` replace or remove only that block). The `local=` line makes AAAA/HTTPS answer NODATA instead of being forwarded upstream, where real IPv6 addresses would bypass the proxy. Never go back to `address=/<d>/::`: `::` reads as loopback, so a nested isx's `DownloadCache` refused every intercepted domain (#814). Never infer ownership from line shapes: an orphaned `local=/<d>/` answers NXDOMAIN for the whole domain. The pre-block layout is detected by its `::` lines and migrated. Anything that rewrites the block takes its domains from `ToolProxyResolver.resolvedDomains()` (all accounts, as the proxy does), never the default account alone.
- **Redirect rule cleanup**: `ProxyService.uninstall(IncusClient)` removes the service **and** unconditionally cleans up PREROUTING redirect rules (`ProxyConfig.clearRedirectRules()`) and bridge DNS overrides (`ProxyConfig.clearBridgeDns()`). `clearRedirectRules()` attempts both firewalld and UFW independently (not else-if) so a system with firewalld installed but inactive still reaches UFW cleanup. Firewalld cleanup falls back to editing the persistent `/etc/firewalld/direct.xml` when the daemon is not running. `runQuiet()` returns `boolean` success; cleanup callers check and warn on failure. `clearRedirectRules()` returns `boolean` so callers like `ResetCommand` can propagate cleanup failures. The no-arg `uninstall()` is private — callers must pass an `IncusClient` so DNS cleanup can reach the bridge.
- `/health` includes the proxy's `pid` only for host callers (`MitmProxy.isHostCaller`); keep any other host-only detail behind the same check, since containers reach this endpoint. `ProxyService.signalAccountRefresh()` reads it at signalling time and falls back to `fuser` for older proxies.
