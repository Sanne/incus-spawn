linux again dependencies	The commands init and isx need on the host: openssl, ssh-keygen and btrfs, installed with the package manager.
linux again incus	Incus provides full Linux system containers — lightweight VMs with near-native performance. This step installs the Incus package, enables its systemd service, and adds your user to the incus-admin group for unprivileged access.
linux again subids	Containers use Linux user namespaces to isolate processes. This configures /etc/subuid and /etc/subgid so the container's root user maps to an unprivileged UID range on the host, preventing privilege escalation.
linux again storage-network	Initializes the Incus daemon with a network bridge and storage pool. If no copy-on-write (btrfs) pool exists, one is created — enabling instant, space-efficient clones when you branch containers.
linux again firewall	Configures the host firewall so containers can reach the internet and resolve DNS. Detects whether firewalld or UFW is active (and installs firewalld when neither is), adds the Incus bridge to a trusted zone, enables NAT masquerading, and sets up FORWARD rules.
linux again mitm-proxy	The MITM proxy intercepts HTTPS from containers and injects your real API credentials, so containers never hold sensitive tokens directly. This step sets up iptables port redirection and generates a custom CA certificate trusted by containers.
linux again ssh-key	Generates a dedicated SSH key pair used only by isx to connect to containers. This is separate from your personal SSH keys and won't interfere with them. Your ~/.ssh/config is updated automatically.
linux again credentials	Choose the credentials your instances may use. Each stays on this computer: isx adds it to requests as they leave an instance, and never puts it inside one.
linux again git-remote-helper	Puts the git-remote-isx helper beside a JVM install of isx, so git can reach instances as remotes.
linux again search-paths	Local directories where isx looks for custom image and tool definitions. Definitions found here can extend or override the built-in templates. Each directory should contain images/ and/or tools/ subdirectories with YAML files.
linux again code-directories	Directories on your host containing git repositories (e.g. ~/code). Enables fast reference clones inside containers and automatic git remote management — repos cloned from these paths get a remote named after the instance, to push and pull directly between container and host without round-tripping through GitHub. Your host files are never directly exposed to containers.
linux again mcp	Lets an agent on this machine (Claude Code or another MCP client) use isx itself: create instances from templates you approve here, run commands in them, and hand tasks to the Claude Code, Codex, Pi, opencode or Antigravity CLI inside them. Agents can never approve templates themselves.
linux again dns	Configures the Incus bridge network so that containers resolve intercepted domains (GitHub, Anthropic, etc.) to the proxy gateway. This lets the MITM proxy transparently inject credentials into HTTPS requests without containers needing any special network configuration.
linux again proxy-service	The MITM proxy intercepts HTTPS traffic from containers and injects real credentials (API keys, tokens) so that containers only ever hold placeholder values. Installing it as a systemd service means it starts automatically on boot — otherwise you'll need to run 'isx proxy start' before launching containers.
